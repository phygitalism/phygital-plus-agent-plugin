## Задача

Запустить генерацию по описанию в `$ARGUMENTS` и довести её до результата.

## Шаги

1. Определи модель. Если в `$ARGUMENTS` её нет — `list_models`, предложи
   варианты и остановись: выбор за человеком, вызов тратит его кредиты.
2. `get_model_schema` для выбранной модели — вход собирается только по этой
   схеме.
3. Файл на входе — канал выбирается по тому, у кого файл и какого он размера,
   а не по качеству: файл уходит как есть, без пережатия и ресайза.
   - байты у тебя и влезают в один вызов — `upload_file`;
   - байты у тебя, но не влезают — `start_upload` → `upload_chunk` →
     `finish_upload`; режь сам файл, а не его base64;
   - можешь сам сделать HTTP-запрос — `get_upload_url` и POST файла с
     выданным пропуском, ключ не нужен;
   - файл у человека — `request_upload` открывает ему панель загрузки; жди,
     пока `storage_object_id` придёт сообщением от него, а если панель вместо
     этого показала ему код — `claim_upload` с этим кодом. Без одного из двух
     id у тебя нет, угадывать его нельзя.

   Вложение из чата переслать нельзя: оно приходит тебе картинкой в контексте,
   а не файлом. Лимиты называет сервер — не держи их в голове.
4. Покажи собранный вход и дождись подтверждения, прежде чем звать `generate`.
5. `generate` → запомни `job_id`. Потеряешь — задачу больше не достать.
6. Опрашивай `get_job` ровно через `poll_after_seconds` из последнего ответа.
   Не ориентируйся на `averageTimeInSeconds`: это худший случай из каталога.
7. Результат покажи ссылкой и картинкой в ответе. Не утверждай, что показал
   файл, если передал только ссылку.

## Чего не делать

Не запускай несколько задач разом и не «пробуй посмотреть, что получится»:
каждый вызов тратит кредиты человека.
